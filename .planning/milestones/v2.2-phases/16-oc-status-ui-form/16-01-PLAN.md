**JS changes -- Add new section AFTER the "Action: Update Specific PO" section (after the closing brace of updateSpecificPO around line 872), BEFORE the closing `</script>` tag:**

Add a status label mapping object and the changeOCStatus function:

```javascript
/* ====================================================================
 * Action: Change OC Status
 * ==================================================================== */

const STATUS_LABELS = {
    OPEN: 'Abierta',
    CLOSED: 'Cerrada',
    CANCELLED: 'Cancelada',
    GENERATED: 'Generada',
};

async function changeOCStatus() {
    const poInput = document.getElementById('change-status-po-input');
    const statusSelect = document.getElementById('change-status-select');
    const poNumber = poInput.value.trim();
    const status = statusSelect.value;

    if (!poNumber) {
        showToast('Ingrese un numero de OC', 'warning');
        return;
    }
    if (!status) {
        showToast('Seleccione un estado', 'warning');
        return;
    }

    const spanishLabel = STATUS_LABELS[status];
    if (!confirmAction(`Cambiar el estado de ${poNumber} a ${spanishLabel} (${status})?`)) {
        return;
    }

    try {
        const result = await apiCall('PUT', '/api/pos/status', {
            poNumber: poNumber,
            status: status,
            tenantIndex: getTenantIndex(),
        });

        if (result.success) {
            showToast(`Estado de ${poNumber} cambiado a ${spanishLabel} (${status})`, 'success');
            poInput.value = '';
            statusSelect.value = '';
        } else {
            showToast(result.summary || result.errors?.join(', ') || 'Error al cambiar estado', 'error');
        }
    } catch (err) {
        showToast('Error: ' + err.message, 'error');
    }
}
```

**Key implementation details:**
- STATUS_LABELS maps English API values to Spanish display labels -- used in confirmation dialog AND success toast for consistency
- Input validation checks both poNumber (empty) and status (not selected) with warning toasts, matching existing patterns
- confirmAction message format: "Cambiar el estado de PO0075624 a Cancelada (CANCELLED)?" per user decision
- Success toast format: "Estado de PO0075624 cambiado a Cancelada (CANCELLED)" per user decision
- Error toast shows result.summary or result.errors?.join(', ') -- same pattern as uploadSpecificPO/updateSpecificPO
- Form clears (both input and select) after success so it's ready for next operation
- UI does NOT reference result.data.idFocaltec (per Phase 15 decision -- filtering at UI layer)
- Uses btn-info with text-white for the button to visually distinguish from Upload (btn-primary) and Update (btn-warning)
