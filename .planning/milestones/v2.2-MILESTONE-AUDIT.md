## E2E Flow: OC Status Change

1. Operator enters OC number in form input
2. Operator selects target status from dropdown (Spanish labels → English API values)
3. Operator clicks "Cambiar Estado" button
4. Client-side validation (empty checks → warning toast)
5. confirmAction() dialog: "Cambiar el estado de {OC} a {Spanish} ({English})?"
6. apiCall('PUT', '/api/pos/status', {poNumber, status, tenantIndex})
7. Request passes requireLicense → requireApiKey → validate(statusUpdateSchema) → writeLimiter
8. Route handler maps poNumber→ocSage, resolves databases[tenantIndex], calls updatePOStatus()
9. updatePOStatus queries FESA for idFocaltec, PUTs to Portal API, updates control table
10. ResultEnvelope returned → sendResult → JSON response
11. UI: success → green toast + form reset | error → red toast with summary message

**Status:** COMPLETE — no breaks in flow
