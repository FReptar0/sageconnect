### Toast feedback (post-POST)

| Path | Copy | Type |
|------|------|------|
| Success — `released: true` | (no toast — modal closes; the next 5s poll hides the card; visual change is sufficient feedback) | n/a |

### Empty state copy (no lock active)

The card itself is hidden (`display: none`) when no operation is active — there is no empty state for Phase 18 because the button does not exist when there is no card to host it. Confirmed via Phase 17 D-07 (`Visibilidad: display:none cuando no hay operaciones activas`) and Phase 18 D-06 (`apenas el polling 5s detecta lock activo, el botón aparece`).

### Intentional copy exceptions

- **`Cancelar`** (modal secondary button): the literal Spanish equivalent of "Cancel" appears on the BLOCK list of generic CTAs that the gsd-ui-checker scans for. This usage is **intentional and approved** — `Cancelar` is the idiomatic Spanish label for a no-op modal dismiss whose only purpose is to abort the destructive flow. The product is monolingual Spanish per D-05; there is no subject noun that would improve clarity for a dismiss-only button. The contrast action `Confirmar liberación` carries the verb+noun specificity. Do not re-flag.

### Destructive confirmation summary

Phase 18 has **one destructive action**: force-releasing the lock. Confirmation pattern:

| Step | Behavior |
|------|----------|
| 1. Operator clicks `Forzar liberación` button | Opens modal via `new bootstrap.Modal('#forceReleaseModal').show()` |
| 2. Modal opens | Default keyboard focus lands on **Cancelar** (not Confirmar) — prevents accidental Enter-confirms |
| 3. Operator presses Esc OR clicks Cancelar OR clicks backdrop | Modal closes via Bootstrap default (no POST fired) |
| 4. Operator clicks Confirmar liberación | Both buttons disable; spinner appears in confirm; POST fires with body `{}` (no `reason` for v1; UI does not collect free-text yet — endpoint still accepts it for future) |
| 5a. POST returns 200 / `released: true` | Modal closes via `bootstrap.Modal#hide()`; next 5s poll hides the card; no toast (intentional — visual change is the feedback) |
| 5b. POST returns 200 / `released: false` (idempotent) | Modal closes; warning toast `El lock ya se había liberado`; card hides on next poll |
| 5c. POST returns 4xx/5xx OR network error | Modal stays open; both buttons re-enable; inline error alert renders inside the modal body BELOW the warning alert; operator can retry |

## Component Inventory

Three new DOM additions in `public/schedule.html`. Each is documented with its exact Bootstrap classes so the planner can scaffold deterministically.

### 1. Force-release button (inside existing card header)

**Location:** inside `<div id="active-operation-card"> > .card-header.d-flex.justify-content-between.align-items-center` (currently lines 169–172). The header today contains: `<span><i class="fas fa-play-circle me-2"></i>Operación en curso</span>` (left) + `<span id="active-op-badge"></span>` (right placeholder, currently empty).

**Insertion point:** REPLACE the empty `#active-op-badge` span with a flex container that holds (a) any future badge AND (b) the new force-release button. Concrete markup:

```html
<div class="d-flex align-items-center gap-2">
    <span id="active-op-badge"></span>
    <button id="btn-force-release"
            type="button"
            class="btn btn-sm btn-outline-danger"
            title="Liberar manualmente el lock background-cycle (admin only)"
            aria-label="Forzar liberación del lock background-cycle"
            data-bs-toggle="modal"
            data-bs-target="#forceReleaseModal">
        <i class="fas fa-unlock-alt me-1"></i>Forzar liberación
    </button>
</div>
```

**Why `btn-outline-danger`:** explicitly selected over `btn-danger` (filled red) because:
- Filled red in the card header would compete visually with the existing dark-blue gradient header strip.
- Outline variant signals "destructive but secondary control" — the *primary* action of this card is observation, not destruction.
- The filled red is reserved for the **modal footer Confirmar** button — at that point the operator has already opted in, so the visual escalation is appropriate.

**Why `data-bs-toggle="modal"`:** Bootstrap 5 declarative pattern — no custom JS click handler needed to OPEN the modal. The submit handler is a separate JS function bound to the modal's confirm button (see Component 3).

**Visibility:** the button lives inside `#active-operation-card`; that card is hidden via `display: none` whenever polling sees no active operation. Because the button DOM is nested inside the hidden card, Phase 18 needs **zero** show/hide logic of its own. The button appears the moment the card appears (D-06 — always visible when card visible).

**Bootstrap classes used:** `.modal`, `.fade`, `.modal-dialog`, `.modal-dialog-centered`, `.modal-content`, `.modal-header`, `.modal-title`, `.btn-close`, `.modal-body`, `.modal-footer`, `.btn-secondary`, `.btn-danger`, `.alert.alert-warning`. **No custom CSS required** — Bootstrap defaults are sufficient.

**ARIA / accessibility contract:**

| Attribute | Value | Why |
|-----------|-------|-----|
| `tabindex="-1"` | on `.modal` | Required by Bootstrap so the modal itself can receive focus |
| `aria-labelledby` | `forceReleaseModalTitle` | Screen reader announces the title when modal opens |
| `aria-describedby` | `forceReleaseModalBody` | Screen reader reads the body content |
| `aria-hidden="true"` | initial state | Bootstrap toggles to `aria-hidden="false"` on show |
| `aria-label="Cerrar"` | on `.btn-close` | Accessible name for the X button |

**Focus management:**

| Event | Behavior | Source |
|-------|----------|--------|
| Modal opens (`shown.bs.modal`) | Initial focus lands on **Cancelar** button (`#btn-force-release-cancel.focus()`). Override Bootstrap's default (which would land on the first focusable element — the close X). | Custom listener on `shown.bs.modal` |
| Operator presses Tab | Focus cycles: Close X → Cancelar → Confirmar liberación → Close X. Bootstrap's built-in focus trap handles this; no custom code. | Bootstrap default |
| Operator presses Esc | Modal closes (Bootstrap default; `keyboard: true`). | Bootstrap default |
| Operator presses Enter while focus is on Confirmar | Triggers click on the focused button (browser default). | Browser default |
| Modal closes (`hidden.bs.modal`) | Focus returns to the element that opened the modal — the `#btn-force-release` button — but if that button no longer exists in DOM (card hidden between open and close), focus falls back to `<body>`. Bootstrap handles return automatically. | Bootstrap default |

**Reduced motion:** Bootstrap 5's `.fade` class respects `prefers-reduced-motion: reduce` natively (CSS variable `--bs-modal-transition` becomes `none`). No additional CSS required.

### 3. Confirm-button JS handler (inline `<script>` block in `schedule.html`)

**Location:** inside the existing inline `<script>` block in `schedule.html` (after the cleanup `beforeunload` listener at line 753). One new public-ish function `submitForceRelease()` and one DOMContentLoaded wiring step.

**State machine:**

| State | Confirm button | Cancel button | Inline error slot |
|-------|----------------|---------------|-------------------|
| Idle (modal just opened) | enabled, label `Confirmar liberación`, icon `fa-unlock-alt` | enabled | hidden (`display: none`) |
| Loading (POST in flight) | disabled, label `Liberando...`, icon `fa-spinner fa-spin` | disabled | hidden |
| Success (200, modal about to close) | (modal closes — state irrelevant after) | (closing) | (closing) |
| Error (4xx/5xx/network) | re-enabled, label restored, icon restored | re-enabled | visible with error message |

**Pseudocode (planner will translate to actual JS in plan tasks):**

```js
async function submitForceRelease() {
    const confirmBtn = document.getElementById('btn-force-release-confirm');
    const cancelBtn  = document.getElementById('btn-force-release-cancel');
    const errorSlot  = document.getElementById('forceReleaseModalError');

    // Loading state
    confirmBtn.disabled = true;
    cancelBtn.disabled = true;
    confirmBtn.innerHTML = '<i class="fas fa-spinner fa-spin me-1"></i>Liberando...';
    errorSlot.style.display = 'none';
    errorSlot.innerHTML = '';

    try {
        const res = await apiCall('POST', '/api/schedule/background-cycle/force-release', {});
        if (res && res.success) {
            // Close modal (bootstrap.Modal.getInstance().hide())
            bootstrap.Modal.getInstance(document.getElementById('forceReleaseModal')).hide();
            // Idempotent path
            if (res.data && res.data.released === false) {
                showToast('El lock ya se había liberado', 'warning');
            }
            // Optimistic UI: hide the card immediately so the operator sees instant feedback
            // (the next 5s poll will confirm + idempotently re-hide if needed)
            hideActiveOperationCard();
        } else {
            throw new Error((res && (res.summary || res.message)) || 'Error desconocido');
        }
    } catch (err) {
        errorSlot.innerHTML = '<div class="alert alert-danger py-2 mb-0">'
            + '<i class="fas fa-times-circle me-2"></i>'
            + 'Error al liberar el lock: ' + (err.message || 'Error desconocido')
            + '. Intentá nuevamente o revisá los logs del servidor.'
            + '</div>';
        errorSlot.style.display = 'block';
    } finally {
        // Restore idle state (no-op if modal already hidden, but harmless)
        confirmBtn.disabled = false;
        cancelBtn.disabled = false;
        confirmBtn.innerHTML = '<i class="fas fa-unlock-alt me-1"></i>Confirmar liberación';
    }
}

// Wire up modal opening to populate the dynamic context line
document.getElementById('forceReleaseModal').addEventListener('show.bs.modal', () => {
    const ctxEl = document.getElementById('forceReleaseModalContext');
    const errorSlot = document.getElementById('forceReleaseModalError');
    errorSlot.style.display = 'none';
    errorSlot.innerHTML = '';

    if (!activeOpSnapshot) {
        ctxEl.innerHTML = '<em>Sin contexto disponible (la operación pudo haberse liberado entre el render y el click).</em>';
        return;
    }
    const shortId = (activeOpSnapshot.operationId || '').substring(0, 8) || '—';
    const startedRel = formatRelative(activeOpSnapshot.startedAt);
    const sp = Array.isArray(activeOpSnapshot.stepProgress) ? activeOpSnapshot.stepProgress : [];
    let stepLabel = '<em>inicializando ciclo</em>';
    if (sp.length > 0) {
        let active = null;
        for (let i = sp.length - 1; i >= 0; i--) {
            if (!sp[i].finishedAt) { active = sp[i]; break; }
        }
        const display = active || sp[sp.length - 1];
        const label = STEP_LABELS[display.step] || display.step;
        const tenantPart = display.tenant ? ' (' + display.tenant + ')' : '';
        stepLabel = '<code>' + label + '</code>' + tenantPart;
    }
    ctxEl.innerHTML = 'Operación <code>' + shortId + '</code>, iniciada ' + startedRel
        + '. Step actual: ' + stepLabel + '.';
});

// Override Bootstrap's default focus to land on Cancelar (not the close X)
document.getElementById('forceReleaseModal').addEventListener('shown.bs.modal', () => {
    document.getElementById('btn-force-release-cancel').focus();
});

// Wire confirm button to the submit function
document.getElementById('btn-force-release-confirm').addEventListener('click', submitForceRelease);
```

**Note for planner:** `STEP_LABELS` is the existing constant in `schedule.html` (line 252) that already maps machine step keys to Spanish labels — reuse, do not duplicate. `formatRelative`, `apiCall`, `showToast`, and `hideActiveOperationCard` are all already declared and reused as-is.
