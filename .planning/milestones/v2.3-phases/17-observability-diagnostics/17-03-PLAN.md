Why a `try/catch` is required (not just `try/finally`): the inner block needs to capture the error message into a variable so the `finally` can pass it to `endStep`. Without the catch, the variable stays null and we lose the failure context in the stepProgress entry. The catch immediately re-throws so the OUTER tenant-level handler (background.js:145) catches it and continues to the next tenant exactly as today.
