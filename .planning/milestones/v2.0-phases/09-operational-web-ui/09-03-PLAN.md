GET /api/payments/uuid-diagnostic?docNbr=PY001&tenantIndex=0
Returns diagnostic info for a specific payment document.

POST /api/payments/uuid-repair/scan -- Body: { "tenantIndex": 0 }
Returns list of repairable UUIDs.

POST /api/payments/uuid-repair/repair -- Body: { "tenantIndex": 0, "dryRun": true|false }
IMPORTANT: dryRun defaults to true on API. When user confirms action, send dryRun: false.

POST /api/payments/uuid-repair/upload -- Body: { "tenantIndex": 0 }
Uploads repaired payments to portal.

POST /api/payments/generate -- Body: { "tenantIndex": 0, "dryRun": true|false }
IMPORTANT: dryRun defaults to true. When user confirms, send dryRun: false (maps to shouldPost=true on backend).

GET /api/payments/cfdis?tenantIndex=0
Returns CFDI Type P invoices from portal.

Two small changes to expose the already-classified payment detail data that `runReconciliation` computes internally but currently discards in the API response.

**1. Add `includeDetails` to Joi schema (`src/routes/schemas/payment-schemas.js`):**

```javascript
includeDetails: Joi.boolean().default(false),
```
This goes alongside the existing `tenantIndex`, `fromDate`, `pyFilter`, `batchLimit`, `dryRun` fields.

**2. Pass `includeDetails` through in `runReconciliation` (`src/scripts/payment-reconciliation.js`):**

In `runReconciliation()` (line ~506), extract the new option:
```javascript
const optIncludeDetails = options.includeDetails === true;
```

Then modify the `successResult` return block (around line 680-696). Currently it returns:
```javascript
categories: {
    ready: categories.ready.length,
    no_providerid: categories.no_providerid.length,
    // ...
},
```

Change to conditionally include the full arrays alongside the counts:

            reason: p.reason
        })),
        no_uuid: categories.no_uuid.map(p => ({
            hdr: { external_id: p.hdr.external_id, provider_external_id: p.hdr.provider_external_id, total_amount: p.hdr.total_amount, bk_currency: p.hdr.bk_currency },
            invoices: (p.invoices || []).map(inv => ({ invoice_external_id: inv.invoice_external_id, UUID: (inv.UUID || '').trim(), invoice_amount: inv.invoice_amount, invoice_currency: inv.invoice_currency })),
            missingCount: p.missingCount, totalCount: p.totalCount
        })),
        not_in_portal: categories.not_in_portal.map(p => ({
            hdr: { external_id: p.hdr.external_id, provider_external_id: p.hdr.provider_external_id, total_amount: p.hdr.total_amount, bk_currency: p.hdr.bk_currency },
            invoices: (p.invoices || []).map(inv => ({ invoice_external_id: inv.invoice_external_id, UUID: (inv.UUID || '').trim(), invoice_amount: inv.invoice_amount, invoice_currency: inv.invoice_currency }))

        }))
    };
}

return successResult(responseData, ...);

  <action>
Create `public/payments.html` following the standard page layout template established in Plan 01.

**Page structure:**

1. **HTML boilerplate:** Bootstrap 5.3 + Font Awesome CDN (same as schedule.html). Lang="es", title "SageConnect - Pagos".

2. **Layout:** `<div class="d-flex">` with sidebar + main content.

3. **Page header:** "Pagos" with fa-credit-card icon. Include a "Ejecutar Conciliacion" button (btn-outline-primary, small) in the header row that re-triggers reconciliation for the current tenant.

4. **Loading state:** Centered spinner shown while reconciliation runs. Replace with content on completion.

5. **Summary cards section** (5 cards in a responsive row):
   Create 5 Bootstrap cards in `<div class="row row-cols-1 row-cols-md-3 row-cols-lg-5 g-3">`:

   | Key | Label | Icon | Color |
   |-----|-------|------|-------|
   | ready | Listos | fa-check-circle | text-success / border-success |
   | no_providerid | Sin PROVIDERID | fa-user-slash | text-warning / border-warning |
   | no_uuid | Sin UUID | fa-fingerprint | text-danger / border-danger |
   | not_in_portal | No en Portal | fa-cloud-slash | text-secondary / border-secondary |
   | provider_mismatch | Proveedor No Coincide | fa-exchange-alt | text-info / border-info |

   Each card:
   - Shows count as large number (fs-2 fw-bold)
   - Shows label below in small text
   - Has `cursor: pointer` and `role="button"`
   - On click: sets active filter to that category (highlight card border with bg opacity), updates table to show only payments from that category
   - Clicking the active card again clears the filter (show all categories)

6. **Results info section** (below cards):
   - Text summary: "Total: X pagos | Tenant: {tenant name}"
   - Total is sum of all 5 category counts

7. **Payment table section** (below info):
   A Bootstrap `<table class="table table-hover">` displaying individual payment rows from `data.details`.

   Table columns: No. Pago (external_id) | Proveedor (provider_external_id) | Monto (total_amount formatted as currency) | Moneda (bk_currency) | Categoria (badge with category color) | Facturas (invoice count)

   Each main row:
   - Has `data-bs-toggle="collapse"` and `data-bs-target="#detail-{external_id}"` attributes
   - Has `role="button"` and `style="cursor:pointer"` for click affordance
   - Shows a small chevron icon (fa-chevron-right) that rotates on expand

   Each main row is followed by a hidden detail row:
   ```html
   <tr>
     <td colspan="6" class="p-0 border-0">
       <div class="collapse" id="detail-{external_id}">
         <div class="p-3 bg-light">
           <h6 class="mb-2">Facturas del Pago {external_id}</h6>
           <table class="table table-sm table-bordered mb-0">
             <thead><tr><th>Factura</th><th>UUID</th><th>Monto</th><th>Moneda</th><th>Pagado</th></tr></thead>
             <tbody>
               <!-- One row per invoice from hdr.invoices -->
               <tr><td>{invoice_external_id}</td><td class="text-monospace small">{UUID}</td><td>{invoice_amount}</td><td>{invoice_currency}</td><td><badge>{FULL_PAID ? 'Pagado' : 'Parcial'}</badge></td></tr>
             </tbody>
           </table>
           <!-- For no_providerid category: show reason text instead of invoice table -->
           <!-- For provider_mismatch: show mismatchDetails below the invoice table -->
         </div>
       </div>
     </td>
   </tr>
   ```

   When a category card filter is active, show only the rows belonging to that category. When no filter, show all payments from all 5 categories (each row tagged with its category via a data-attribute like `data-category="ready"`).

8. **Action buttons section** (row of buttons below cards, above table):
   - "Subir Pagos Listos" (btn-success, fa-upload icon): Only enabled if `ready > 0`
     - On click: `confirmAction('Subir pagos listos al portal? Esta accion no se puede deshacer.')`
     - If confirmed: POST /api/payments/generate with `{ tenantIndex, dryRun: false }`
     - Show toast on success/error
   - "Escanear UUIDs Reparables" (btn-warning, fa-search icon):
     - On click: POST /api/payments/uuid-repair/scan with `{ tenantIndex }`
     - Show result count in a toast or inline display
   - "Reparar UUIDs" (btn-danger, fa-wrench icon):
     - On click: `confirmAction('Reparar UUIDs faltantes? Esto modificara registros en Sage.')`
     - If confirmed: POST /api/payments/uuid-repair/repair with `{ tenantIndex, dryRun: false }`
     - Show toast on success/error
   - "Ver CFDIs Tipo P" (btn-info, fa-file-invoice icon):
     - On click: GET /api/payments/cfdis?tenantIndex=X
     - Show results in a modal or expandable section below

9. **UUID Diagnostic section** (below table):
   Input field where user can type a document number (docNbr) and click "Buscar" to call GET /api/payments/uuid-diagnostic. Display the diagnostic result below the input as a detail card showing header info, invoice list, and diagnosis.

10. **Toast container:** Standard toast container div.

11. **JavaScript organization:**
    - Load shared.js first
    - `DOMContentLoaded`: call `initPage('/payments.html')` then `loadPaymentsData()`
    - `loadPaymentsData()`: POST /api/payments/reconciliation with `{ tenantIndex: getTenantIndex(), includeDetails: true }`
    - Store the full response in a module-level variable (e.g., `let reconciliationData = null`)
    - `renderCategoryCards(categories)`: builds the 5 cards HTML with counts
    - `renderPaymentTable(details, activeFilter)`: builds table rows from `details`. Combines all 5 arrays into one flat list, each tagged with its category. When `activeFilter` is set, only show that category.
    - `filterByCategory(key)`: sets `activeFilter`, highlights selected card, calls `renderPaymentTable` with filter
    - `clearFilter()`: resets all card highlights, re-renders full table
    - `window.onTenantChange = () => loadPaymentsData()` -- re-run reconciliation when tenant changes

**CRITICAL: dryRun handling.** When user confirms a destructive action, ALWAYS pass `dryRun: false` in the request body. The API defaults to dryRun: true, so without explicit false, nothing happens (Pitfall 6 from research).

**All text in Spanish.** Labels, buttons, messages, notes -- everything in Spanish.
