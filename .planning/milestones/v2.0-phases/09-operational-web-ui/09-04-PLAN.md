<!-- API endpoints this page consumes. All require x-api-key header. -->

POST /api/pos/lifecycle -- Body: { "mode": "analyze", "tenantIndex": 0 }
Returns analysis of PO statuses for the tenant. Used for status overview.
```json
{
  "success": true,
  "data": { /* analysis results with status counts */ },
  "summary": "Analysis completed"
}
```

GET /api/pos/diagnostic?poNumber=OC-001&database=FESA&empresa=EMPRESA
Returns diagnostic info for a specific PO.
```json
{
  "success": true,
  "data": { /* PO diagnostic details */ }
}
```

GET /api/pos/query?poNumbers=OC-001,OC-002&database=FESA&tenantIndex=0
Query specific POs without posting.

POST /api/pos/upload -- Body: { "poNumbers": "OC-001", "database": "FESA", "tenantIndex": 0 }
Upload specific POs to portal.

PUT /api/pos/update -- Body: { "poNumber": "OC-001", "database": "FESA", "tenantIndex": 0, "dryRun": true }
IMPORTANT: dryRun defaults to true. Send dryRun: false on confirmed action.

POST /api/pos/upload-authorized -- Body: { "tenantIndex": 0 }
Upload today's authorized POs.

GET /api/pos/address-diagnostic?poNumber=OC-001&database=FESA
Address diagnostic for a PO.

GET /api/pos/payment-form-diagnostic?poNumber=OC-001&database=FESA
Payment form diagnostic for a PO.

Tenant structure (from config.portal.tenants):
- Each tenant has: { id, key, secret, database, externalId }
- database field is used as display name and as "database" param in API calls

  <action>
Create `public/pos.html` following the standard page layout template. Mirrors the payment view pattern for visual consistency (per user decision).

**Page structure:**

1. **HTML boilerplate:** Bootstrap 5.3 + Font Awesome CDN. Lang="es", title "SageConnect - Ordenes de Compra".

2. **Layout:** `<div class="d-flex">` with sidebar + main content.

3. **Page header:** "Ordenes de Compra" with fa-file-invoice icon. Include a "Actualizar" refresh button (btn-outline-primary, small) to re-fetch all data.

4. **Loading state:** Centered spinner while initial data loads.

5. **PO diagnostic search section** (top, prominently placed per user decision):
   - Input group: text input (placeholder "Buscar OC por numero...") + "Buscar" button (btn-primary, fa-search icon)
   - On search: GET /api/pos/diagnostic with poNumber, database from current tenant (use `window.__TENANTS__[getTenantIndex()].name` for database), empresa from config if available or omit
   - Results displayed below search in a card:
     - Show all diagnostic fields from the API response
     - If data is an object, render key-value pairs in a table
     - If error: show error message in an alert
   - Include secondary action buttons next to search: "Diagnostico de Direccion" and "Diagnostico Forma de Pago" that call the respective diagnostic endpoints for the searched PO number
   - Clear previous results when starting a new search

6. **Status overview section** (summary cards):
   Use POST /api/pos/lifecycle with `{ mode: 'analyze', tenantIndex: getTenantIndex() }` to get PO status analysis.

   Display 3 summary cards in `<div class="row row-cols-1 row-cols-md-3 g-3">`:

   | Status | Label | Icon | Color |
   |--------|-------|------|-------|
   | posted | Publicadas | fa-check-circle | text-success / border-success |
   | error | Con Error | fa-times-circle | text-danger / border-danger |
   | pending | Pendientes | fa-clock | text-warning / border-warning |

   Each card:
   - Shows count as large number
   - Label below
   - Clickable to filter (same pattern as payments)

   NOTE: The actual status field names in the API response may vary. The executor should inspect the lifecycle analyze response and map available status groupings to these 3 categories. If the response structure doesn't have these exact keys, adapt the card rendering to whatever the analyze endpoint returns (it likely returns grouped PO data).

7. **Today's authorized POs section:**
   - A card titled "OCs Autorizadas Hoy"
   - On page load (and on tenant change), call POST /api/pos/upload-authorized with `{ tenantIndex }` but treat it as a read operation first -- if the endpoint requires explicit "list" vs "upload" behavior, use it with dry intent
   - Actually, since upload-authorized is a POST that UPLOADS, do NOT auto-call it on page load. Instead:
     - Display a button "Ver OCs Autorizadas Hoy" (btn-info)
     - ALTERNATIVE: Use GET /api/pos/query or POST /api/pos/lifecycle with analyze mode which may return today's authorized list
     - Show the "Subir OCs Autorizadas" (btn-success) action button that on click + confirm triggers POST /api/pos/upload-authorized with `{ tenantIndex }`
   - Display results as a compact table or list when available

8. **Action buttons section:**
   - "Subir OCs Autorizadas" (btn-success, fa-upload icon):
     - On click: `confirmAction('Subir ordenes de compra autorizadas al portal?')`
     - If confirmed: POST /api/pos/upload-authorized with `{ tenantIndex: getTenantIndex() }`
     - Show toast on success/error
   - "Actualizar OC" (btn-warning, fa-sync icon):
     - Shows a small form/modal: input for PO number + confirm
     - On confirm: PUT /api/pos/update with `{ poNumber, database, tenantIndex, dryRun: false }`
     - CRITICAL: Send dryRun: false when user confirms (Pitfall 6)
   - "Subir OC Especifica" (btn-primary, fa-upload icon):
     - Shows input for PO number(s)
     - On confirm: POST /api/pos/upload with `{ poNumbers, database, tenantIndex }`

9. **Toast container:** Standard toast container div.

10. **JavaScript organization:**
    - Load shared.js first
    - `DOMContentLoaded`: call `initPage('/pos.html')` then `loadPOData()`
    - `loadPOData()`: POST /api/pos/lifecycle with analyze mode to get status overview
    - `searchPO(poNumber)`: GET /api/pos/diagnostic
    - `renderStatusCards(data)`: builds the 3 status cards
    - `renderDiagnosticResult(data)`: displays diagnostic results
    - `window.onTenantChange = () => loadPOData()` -- reload on tenant switch
    - Helper to get current tenant database name: `window.__TENANTS__[getTenantIndex()]?.name || ''`

**CRITICAL: dryRun handling.** Same as payments -- when user confirms destructive action, pass `dryRun: false`. The API defaults protect against accidental execution.

**All text in Spanish.** Consistent with payment view pattern.
