<interfaces>
<!-- API endpoints this page consumes -->

GET /api/schedule -- returns:
```json
{
  "success": true,
  "data": {
    "tasks": [{
      "taskId": "background-cycle",
      "cronExpression": "*/15 * * * *",
      "status": "idle|running|not-initialized",
      "nextRun": "ISO string or null",
      "lastRun": "ISO string or null"
    }]
  }
}
```

GET /api/schedule/history -- returns:
```json
{
  "success": true,
  "data": {
    "executions": [
      {
        "taskId": "background-cycle",
        "operationId": "uuid",
        "startedAt": "ISO",
        "finishedAt": "ISO",
        "success": true,
        "errors": [],
        "summary": "Background cycle completed"
      }
    ],
    "count": 5
  }
}
```

POST /api/schedule/:taskId/trigger -- requires x-api-key header. Returns:
```json
{
  "success": true,
  "data": {
    "operationId": "uuid",
    "taskId": "background-cycle",
    "message": "Task triggered"
  }
}
```
Or 409 if already running:
```json
{
  "success": false,
  "errors": ["Background cycle is already running"],
  "summary": "Conflict"
}
```

GET /api/operations/:operationId/stream -- SSE stream. Events:
```
event: progress
data: {"type":"progress","operation":"background-cycle","tenant":"TENANT_ID","step":"buildProviders|downloadCFDI|checkPayments|uploadPayments|createPurchaseOrders|processOrderChanges|closePurchaseOrders","message":"...","timestamp":"ISO"}

event: complete
data: {"type":"complete","operation":"background-cycle","message":"...","timestamp":"ISO"}
```

GET /api/operations/status -- returns:
```json
{
  "success": true,
  "data": {
    "operations": [{ "taskId": "background-cycle", "operationId": "uuid", "startedAt": "ISO" }]
  }
}
```

- showToast(message, type) -- Bootstrap toast notification
- formatDateTime(isoString) -- Spanish locale date/time
- getTenantIndex() -- current tenant from localStorage
- confirmAction(message) -- window.confirm wrapper

  <action>
Create `public/schedule.html` with the standard page layout template from research.

**Page structure:**

1. **HTML boilerplate:** Same CDN links as existing dashboard (Bootstrap 5.3, Font Awesome 6.4). Add cronstrue CDN for human-readable cron: `<script src="https://unpkg.com/cronstrue@3.14.0/dist/cronstrue.min.js"></script>` and `<script src="https://unpkg.com/cronstrue@3.14.0/locales/es.min.js"></script>`. Lang="es", title "SageConnect - Programacion".

2. **Layout wrapper:** `<div class="d-flex">` containing sidebar div + main content area.

3. **Page header:** "Programacion" with fa-calendar-check icon, inside `<div class="p-3 border-bottom bg-white">`.

4. **Schedule status section** (top area):
   - A Bootstrap card showing:
     - Task name ("Ciclo de Fondo") as card title
     - Status badge: idle=bg-secondary "Inactivo", running=bg-success+spinner "Ejecutando", not-initialized=bg-warning "No inicializado"
     - Cron expression raw value AND human-readable via cronstrue: `cronstrue.toString(cronExpression, { locale: 'es' })`
     - Next run: formatted with `formatDateTime()`
     - Last run: formatted with `formatDateTime()`
     - "Ejecutar Ahora" button (btn-primary, fa-play icon)
       - On click: calls `confirmAction('Iniciar ciclo de fondo manualmente?')`
       - If confirmed: POST /api/schedule/background-cycle/trigger via `apiCall('POST', '/api/schedule/background-cycle/trigger')`
       - On success: show toast "Ciclo iniciado", extract operationId from response.data.operationId, call `connectSSE(operationId)`, update status to "running"
       - On 409: show toast "El ciclo ya esta en ejecucion" (type 'warning')
       - On other error: show toast with error message (type 'error')

5. **Real-time timeline section** (below status):
   - A card titled "Progreso en Tiempo Real"
   - Contains `<div id="timeline">` initially showing "Sin actividad reciente" placeholder
   - When a cycle starts (via trigger or detected via polling), connects SSE and populates timeline
   - Each timeline step: vertical list with icon + label + tenant + timestamp
     - In-progress step: fa-spinner fa-spin text-primary
     - Completed step: fa-check-circle text-success
     - Step labels in Spanish (from research):
       ```
       buildProviders: 'Construir Proveedores XML'
       downloadCFDI: 'Descargar CFDIs'
       checkPayments: 'Verificar Pagos'
       uploadPayments: 'Subir Pagos'
       createPurchaseOrders: 'Crear Ordenes de Compra'
       processOrderChanges: 'Procesar Cambios de Ordenes'
       closePurchaseOrders: 'Cerrar Ordenes de Compra'
       ```
   - On 'complete' event: mark all steps as complete, close EventSource, show toast "Ciclo completado"
   - On page unload (`beforeunload` event): call `evtSource.close()` to prevent orphaned connections

6. **Execution history section** (below timeline):
   - A card titled "Historial de Ejecuciones"
   - Bootstrap table with columns: Fecha/Hora, Duracion, Estado, Errores, Resumen
   - Fetch from GET /api/schedule/history on page load
   - Each row:
     - Fecha/Hora: `formatDateTime(execution.startedAt)`
     - Duracion: calculated from startedAt/finishedAt difference, formatted as "Xm Ys" or "Xs"
     - Estado: badge -- success=bg-success "Exitoso", failed=bg-danger "Error"
     - Errores: count of errors array, show 0 for empty
     - Resumen: execution.summary text
   - Sort by startedAt descending (most recent first)
   - Show "No hay historial" when empty

7. **Loading state:** Show spinner while fetching schedule data. Replace with content once loaded.

8. **Toast container:** `<div id="toast-container" class="toast-container position-fixed top-0 end-0 p-3" style="z-index: 1100;"></div>`

9. **Auto-detect running operations on page load:**
   - After fetching schedule status, if status is "running", also fetch GET /api/operations/status
   - If there's a running background-cycle operation, auto-connect SSE to its operationId
   - This handles the case where user navigates to page during an already-running cycle

**JavaScript organization:**
- `<script src="/js/shared.js"></script>` before page-specific script
- Page-specific code in inline `<script>` block:
  - `DOMContentLoaded` handler calls `initPage('/schedule.html')` then `loadScheduleData()`
  - `loadScheduleData()` fetches /api/schedule and /api/schedule/history in parallel
  - `renderScheduleStatus(task)` renders the status card
  - `renderHistory(executions)` renders the history table
  - `connectSSE(operationId)` creates EventSource, handles progress/complete events
  - `addTimelineStep(data)` appends step to timeline
  - `markTimelineComplete()` marks all steps as done
  - `window.onTenantChange` does NOT need to reload schedule data -- schedule is global, not per-tenant

**All text in Spanish.** No English-facing labels.
