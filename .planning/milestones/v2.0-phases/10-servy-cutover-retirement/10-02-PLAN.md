    **Create `scripts/install-service.ps1`:**

    Idempotent PowerShell script that registers SageConnect as a Windows Service via Servy. Must be safe to run multiple times.

    Script requirements:
    - Accept parameters with defaults: `-InstallDir` (default `E:\sageconnect`), `-NodePath` (default `C:\Program Files\nodejs\node.exe`), `-ServiceName` (default `SageConnect`), `-Port` (default `3030`)
    - **Pre-flight checks:**
      1. Verify running as Administrator (Servy requires elevated privileges)
      2. Check if `servy-cli` is available on PATH (if not, print instructions: `winget install servy`)
      3. Check if Node.js exists at `-NodePath`
      4. Check if `-InstallDir` exists and contains `src/index.js`
      5. Check if service already exists via `Get-Service -Name $ServiceName` -- if running, print status and exit 0. Do NOT re-register.
    - **Installation:** Use `servy-cli install` with these flags:
      - `--name=$ServiceName`, `--displayName="SageConnect"`, `--description="Sage 300 - Portal de Proveedores integration service"`
      - `--path=$NodePath`, `--params="src/index.js"`, `--startupDir=$InstallDir`
      - `--startupType="Automatic"` (auto-start on boot)
      - `--stdout="$InstallDir\logs\servy-stdout.log"`, `--stderr="$InstallDir\logs\servy-stderr.log"`
      - `--enableHealth`, `--heartbeatInterval=30`, `--maxFailedChecks=3`
      - `--recoveryAction="RestartService"`, `--maxRestartAttempts=5`
      - `--enableSizeRotation`, `--rotationSize=10`, `--maxRotations=5`
      - `--stopTimeout=30`
    - **Post-install:** Start the service, verify it is running via `Get-Service`, print status
    - **Health check note:** Include a comment explaining Servy's `--enableHealth` monitors process health. If HTTP polling is needed in the future, configure Servy's health URL to `http://localhost:$Port/api/system/health`
    - Use `Write-Host` with colors for success/error/warning messages
    - Exit codes: 0 = success or already exists, 1 = pre-flight failure

    2. **Procedimiento de Cutover** (from CONTEXT.md locked decision):
       - Paso 1: Detener la tarea programada en Windows Task Scheduler
       - Paso 2: Verificar que no hay procesos node.exe corriendo (`tasklist /fi "imagename eq node.exe"`)
       - Paso 3: Desplegar codigo v2.0 (copiar archivos, `npm install --production`)
       - Paso 4: Ejecutar `scripts/install-service.ps1` como Administrador
       - Paso 5: Verificar servicio: `Get-Service SageConnect`, visitar `http://localhost:3030/schedule.html`

    3. **Verificacion**
       - `Get-Service SageConnect` muestra Running
       - `http://localhost:3030/api/system/health` retorna status ok
       - Dashboard web accesible en `http://localhost:3030`
       - Revisar logs: `E:\sageconnect\logs\servy-stdout.log`

    4. **Comandos Utiles**
       - Reiniciar: `Restart-Service SageConnect` or `servy-cli restart --name=SageConnect`
       - Detener: `Stop-Service SageConnect` or `servy-cli stop --name=SageConnect`
       - Ver estado: `Get-Service SageConnect` or `servy-cli status --name=SageConnect`
       - Desinstalar: `servy-cli uninstall --name=SageConnect`
       - Ver logs Servy: `E:\sageconnect\logs\servy-stdout.log`

    5. **Rollback** (from CONTEXT.md locked decision):
       - Detener servicio: `Stop-Service SageConnect`
       - Desinstalar servicio: `servy-cli uninstall --name=SageConnect`
       - Restaurar `RunSageconnect.bat` desde backup del servidor (no esta en el repo)
       - Re-habilitar tarea programada en Windows Task Scheduler
       - El codigo v2.0 sigue funcionando con `npm start` (no requiere revert de codigo)

    6. **Troubleshooting**
       - Servicio no inicia: verificar .env, revisar `servy-stderr.log`
       - Puerto 3030 ocupado: `netstat -ano | findstr :3030`, matar proceso
       - Servy no encontrado: `winget install servy`, reiniciar terminal
