<objective>
Fix test infrastructure broken by the env unification migration so all real Jest tests run to completion.

Purpose: The migration to centralized config.js with fail-fast validation introduced a regression: test files that import modules which `require('../config')` now crash with `process.exit(1)` because env vars are missing in the test environment. Additionally, three utility scripts in `tests/` are misidentified as Jest tests by `testMatch`, causing spurious crashes. This plan fixes both issues so `npm test` produces a clean, interpretable result.

Output: All genuine Jest test suites run to completion. Non-Jest utility scripts excluded. Pre-existing failures (TransformTime 2/3, PaymentReconciliation 1/24) remain documented but are NOT regressions from the migration.

**Root cause of crashes:** `src/config.js` calls `validate()` at module load time (line 58). When any module `require('../config')` is loaded during tests without env vars set, it hits `process.exit(1)`. Before migration, modules loaded dotenv independently and didn't validate.

**TimezoneHelper special complexity:** The test does `delete require.cache[...]` and re-requires TimezoneHelper in several tests (lines 34, 61, 232, 240), which re-triggers config require. The config mock must handle these re-require cycles.

**EmailSender.test.js:** This is an integration test that calls `sendMail()` expecting real SMTP config. It will never pass without real credentials. It should be marked as an integration test or skipped in CI.
