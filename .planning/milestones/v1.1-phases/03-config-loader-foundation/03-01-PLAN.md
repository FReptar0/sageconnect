<feature>
  <name>Centralized Config Loader with Validation</name>
  <files>src/config.js, tests/config.test.js</files>
  <behavior>
    RED phase -- write tests first defining these behaviors:

    1. Structure tests:
       - config.database has keys: user, password, server, database (mapped from USER, PASSWORD, SERVER, DATABASE)
       - config.portal.url is a string (mapped from URL)
       - config.portal.tenants is an array of objects with keys: id, key, secret, database, externalId
         (parsed from comma-separated TENANT_ID, API_KEY, API_SECRET, DATABASES, EXTERNAL_IDS)
       - For single tenant: tenants array has length 1
       - For multi-tenant (e.g., "t1,t2"): tenants array has length 2, each with correct id/key/secret/database/externalId
       - config.mailing.transport is string (mapped from MAIL_TRANSPORT, new var)
       - config.mailing.notices is array (split from MAILING_NOTICES)
       - config.mailing.cc is array (split from MAILING_CC)
       - config.mailing.port is number (parsed from ePuerto)
       - config.mailing.ssl is boolean (parsed from eSSL === 'TRUE')
       - config.paths has keys: downloads, providers, logs (mapped from PATH, PROVIDERS_PATH, LOG_PATH)
       - config.app.defaultAddress is nested object with 7 keys
       - config.app.addressIdentifiersSkip is array (split from ADDRESS_IDENTIFIERS_SKIP)
       - config.app.autoTerminate is boolean (parsed from AUTO_TERMINATE === 'true')

    2. Validation tests:
       - Missing one required database var -> exits with code 1, error message includes var name and "(database)"
       - Missing one required portal var -> exits with code 1, error message includes var name and "(portal)"
       - Missing one required paths var -> exits with code 1, error message includes var name and "(paths)"
       - Missing one required app var -> exits with code 1, error message includes var name and "(app)"
       - Empty string for required var -> treated as missing (same exit behavior)
       - Multiple missing vars -> all listed in single error message
       - Error message format: "[CONFIG ERROR] Missing required environment variables:" followed by list
       - Error message ends with "See .env.example for reference.\nProcess exiting."

    3. Mailing optional tests:
       - All mailing vars missing -> config.mailing is empty/defaults, NO exit, NO error
       - Some mailing vars present -> config.mailing populated with what's available

    4. Backward compat test:
       - After requiring config, process.env.USER (etc.) is populated (dotenv.config was called internally)

    Testing approach:
    - Use jest.spyOn(process, 'exit').mockImplementation() to capture exit calls
    - Set process.env vars directly in beforeEach, clear in afterEach
    - Use jest.isolateModules() or delete require.cache to re-require config.js fresh per test
    - Do NOT mock dotenv -- instead set env vars directly since config.js will call dotenv.config() which reads from .env, but tests override via process.env
  </behavior>
  <implementation>
    GREEN phase -- implement src/config.js to pass all tests:

    1. At module top: `const dotenv = require('dotenv');` then `dotenv.config();` (loads single .env from project root, populates process.env)

    2. Define REQUIRED_VARS object organized by section:
       ```
       const REQUIRED = {
         database: ['USER', 'PASSWORD', 'SERVER', 'DATABASE'],
         portal: ['URL', 'TENANT_ID', 'API_KEY', 'API_SECRET', 'DATABASES', 'EXTERNAL_IDS'],
         paths: ['PATH', 'PROVIDERS_PATH', 'LOG_PATH'],
         app: ['IMPORT_CFDIS_ROUTE', 'ARG', 'NOMBRE', 'RFC', 'REGIMEN', 'TIMEZONE',
               'DEFAULT_ADDRESS_CITY', 'DEFAULT_ADDRESS_COUNTRY', 'DEFAULT_ADDRESS_IDENTIFIER',
               'DEFAULT_ADDRESS_MUNICIPALITY', 'DEFAULT_ADDRESS_STATE', 'DEFAULT_ADDRESS_STREET',
               'DEFAULT_ADDRESS_ZIP', 'ADDRESS_IDENTIFIERS_SKIP']
       };
       ```

    3. Validation function that collects ALL missing vars across all sections, then prints formatted error and calls process.exit(1) if any missing. Empty string (`(val || '').trim() === ''`) counts as missing.

    4. Build config object reading from process.env:
       - Multi-tenant parsing: split TENANT_ID by comma, zip with API_KEY, API_SECRET, DATABASES, EXTERNAL_IDS splits to create array of tenant objects
       - Mailing: only populate if MAIL_TRANSPORT is set; parse port to number, ssl to boolean, split notices/cc
       - App: parse AUTO_TERMINATE to boolean, split ADDRESS_IDENTIFIERS_SKIP to array, nest defaultAddress

    5. `module.exports = config;` (direct export, not a function -- per user's decision to use `require('./config')` directly)
  </implementation>
</feature>
