**Compuerta con reloj inyectado y fail-closed** (`shouldDispatchPaymentReport`, `:151-179`):

```js
function shouldDispatchPaymentReport(now, sentinelPath, reportConfig) {
    // Fail-closed on bad input — never dispatch on a malformed call.
    if (!reportConfig || typeof reportConfig !== 'object') {
        return false;
    }
    if (!reportConfig.enabled) {
        return false;
    }
    if (!(now instanceof Date) || Number.isNaN(now.getTime())) {
        return false;
    }
    if (typeof sentinelPath !== 'string' || sentinelPath.length === 0) {
        return false;
    }

    // Sin término de día, a propósito (D-07): el periodo lo lleva la ruta del
    // centinela, que el llamador arma con paymentPeriodOf(now). Añadir aquí una
    // comparación de día exacto haría que un servicio caído ese día perdiera el
    // reporte del periodo, en silencio y para siempre.
    if (now.getHours() < reportConfig.hour) {
        return false;
    }

    if (fs.existsSync(sentinelPath)) {
        return false;
    }

    return true;
}
```

Qué cambia en la decisión nueva:

- es pura: recibe ya leídos el estado de D y el de ayer, sin `fs.existsSync`;
- compara hora Y minuto (`now.getHours()` / `now.getMinutes()` contra `{ hour, minute }`);
- devuelve una ACCIÓN, no un booleano: crear `pending`, abandonar ayer, intentar D, intentar ayer o nada.

Se conserva el orden fail-closed: objeto de config → `enabled` → `Date` válida.

**Ayudante puro que devuelve `null` ante entrada mala** (`paymentPeriodOf`, `:108-113`). Es el molde para «último día» y para clasificar motivos.

```js
function paymentPeriodOf(date) {
    if (!(date instanceof Date) || Number.isNaN(date.getTime())) {
        return null;

    return date.getDate() <= 15 ? 1 : 2;
}
```
