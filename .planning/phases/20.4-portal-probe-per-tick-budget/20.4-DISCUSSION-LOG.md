## Findings surfaced before the question (not user decisions)

Two properties of the existing code were read out of `PortalOC_Creator.js` and stated to the user before any option was offered, because both change what "correct" means for this phase:

1. **RETRY-E1's wording is a reading hazard.** *"The gate additionally requires both budget-remaining and count-remaining to be true"* reads naturally as `if (priorErrors > 0 && budgetLeft && countLeft)`. That form falls through to the POST when the gate goes false, which is the exact opposite of RETRY-E3 and would re-manufacture the duplicate-POST / 409 that Phase 20.3 exists to eliminate. Locked as **CONTEXT D-04**: nested early `continue`.
2. **The summary is skipped when `probed === 0`** (`PortalOC_Creator.js:562`, 20.3's D-06). Combined with a function-entry clock origin, `probed === 0 && deferred > 0` is reachable, so the worst tick would print nothing. Became the second question below and is locked as **CONTEXT D-07**.

**User's choice:** delegated to Claude.
**Notes:** decided for the function-entry origin (CONTEXT D-01). The ceiling being protected belongs to the step, not to the probe, and the relational guard's arithmetic (120 s probe + 180 s remaining = 300 s) only closes if both sides share an origin. Accepted cost: a slow SELECT can leave zero probes that tick — fail-closed, and made visible by D-07.
