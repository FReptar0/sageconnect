<!-- API endpoints this page consumes. All require x-api-key header (mounted behind requireApiKey). -->

POST /api/payments/reconciliation
Body: { "tenantIndex": 0 }
Returns:
```json
{
  "success": true,
  "data": {
    "categories": {
      "ready": 5,
      "no_providerid": 2,
      "no_uuid": 1,
      "not_in_portal": 0,
      "provider_mismatch": 3
    }
  },
  "summary": "Reconciliation completed"
}
```
NOTE: Returns COUNTS only, not full payment arrays (Phase 7 decision: lightweight API responses).
The UI shows category counts in summary cards. Individual payment records are NOT available from this endpoint.

GET /api/payments/uuid-diagnostic?docNbr=PY001&tenantIndex=0
Returns diagnostic info for a specific payment document.

POST /api/payments/uuid-repair/scan -- Body: { "tenantIndex": 0 }
Returns list of repairable UUIDs.

POST /api/payments/uuid-repair/repair -- Body: { "tenantIndex": 0, "dryRun": true|false }
IMPORTANT: dryRun defaults to true on API. When user confirms action, send dryRun: false.

POST /api/payments/uuid-repair/upload -- Body: { "tenantIndex": 0 }
Uploads repaired payments to portal.

POST /api/payments/generate -- Body: { "tenantIndex": 0, "dryRun": true|false }
IMPORTANT: dryRun defaults to true. When user confirms, send dryRun: false (maps to shouldPost=true on backend).

GET /api/payments/cfdis?tenantIndex=0
Returns CFDI Type P invoices from portal.

  <action>
Create `public/payments.html` following the standard page layout template.

**Page structure:**

1. **HTML boilerplate:** Bootstrap 5.3 + Font Awesome CDN (same as schedule.html). Lang="es", title "SageConnect - Pagos".

2. **Layout:** `<div class="d-flex">` with sidebar + main content.

3. **Page header:** "Pagos" with fa-credit-card icon. Include a "Ejecutar Conciliacion" button (btn-outline-primary, small) in the header row that re-triggers reconciliation for the current tenant.

4. **Loading state:** Centered spinner shown while reconciliation runs. Replace with content on completion.

5. **Summary cards section** (5 cards in a responsive row):
   Create 5 Bootstrap cards in `<div class="row row-cols-1 row-cols-md-3 row-cols-lg-5 g-3">`:

   | Key | Label | Icon | Color |
   |-----|-------|------|-------|
   | ready | Listos | fa-check-circle | text-success / border-success |
   | no_providerid | Sin PROVIDERID | fa-user-slash | text-warning / border-warning |
   | no_uuid | Sin UUID | fa-fingerprint | text-danger / border-danger |
   | not_in_portal | No en Portal | fa-cloud-slash | text-secondary / border-secondary |
   | provider_mismatch | Proveedor No Coincide | fa-exchange-alt | text-info / border-info |

   Each card:
   - Shows count as large number (fs-2 fw-bold)
   - Shows label below in small text
   - Has `cursor: pointer` and `role="button"`
   - On click: sets active filter to that category (highlight card border), updates UI
   - Clicking the active card again clears the filter (show all)

6. **Results info section** (below cards):
   - Text summary: "Total: X pagos | Tenant: {tenant name}"
   - Total is sum of all 5 category counts

7. **Action buttons section** (row of buttons below cards):
   - "Subir Pagos Listos" (btn-success, fa-upload icon): Only enabled if `ready > 0`
     - On click: `confirmAction('Subir pagos listos al portal? Esta accion no se puede deshacer.')`
     - If confirmed: POST /api/payments/generate with `{ tenantIndex, dryRun: false }`
     - Show toast on success/error
   - "Escanear UUIDs Reparables" (btn-warning, fa-search icon):
     - On click: POST /api/payments/uuid-repair/scan with `{ tenantIndex }`
     - Show result count in a toast or inline display
   - "Reparar UUIDs" (btn-danger, fa-wrench icon):
     - On click: `confirmAction('Reparar UUIDs faltantes? Esto modificara registros en Sage.')`
     - If confirmed: POST /api/payments/uuid-repair/repair with `{ tenantIndex, dryRun: false }`
     - Show toast on success/error
   - "Ver CFDIs Tipo P" (btn-info, fa-file-invoice icon):
     - On click: GET /api/payments/cfdis?tenantIndex=X
     - Show results in a modal or expandable section below

8. **Reconciliation detail note:**
   Since the reconciliation API returns COUNTS only (not individual payment records -- Phase 7 decision), the table section shows the category breakdown with counts. Display a note: "La conciliacion muestra conteos por categoria. Para detalles de pagos individuales, use las acciones de diagnostico."

   If you want to show more detail, add a "Diagnostico UUID" input field where the user can type a document number (docNbr) and click "Buscar" to call GET /api/payments/uuid-diagnostic. Display the diagnostic result below the input as a detail card.

9. **Toast container:** Standard toast container div.

10. **JavaScript organization:**
    - Load shared.js first
    - `DOMContentLoaded`: call `initPage('/payments.html')` then `loadPaymentsData()`
    - `loadPaymentsData()`: POST /api/payments/reconciliation with `{ tenantIndex: getTenantIndex() }`
    - `renderCategoryCards(categories)`: builds the 5 cards HTML
    - `filterByCategory(key)`: highlights selected card, updates display
    - `clearFilter()`: resets all card highlights
    - `window.onTenantChange = () => loadPaymentsData()` -- re-run reconciliation when tenant changes

**CRITICAL: dryRun handling.** When user confirms a destructive action, ALWAYS pass `dryRun: false` in the request body. The API defaults to dryRun: true, so without explicit false, nothing happens (Pitfall 6 from research).

**All text in Spanish.** Labels, buttons, messages, notes -- everything in Spanish.
