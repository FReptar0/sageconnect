<objective>
Harden `computeRetryEligibility` for the new reality that `now` becomes a SQL-sourced value (D-01), and
rewrite the JSDoc paragraph that this phase invalidates.

Purpose: the helper's contract promises it "fails OPEN, never throws", and it does — for `lastErrorAt`
and `intervalMinutes`. It does **not** for `now`. Verified by execution against a row whose last error
is 300 minutes old with a 240-minute interval (correct answer: eligible):

| `now` passed | result |
|---|---|
| a `Date` | eligible ✓ |
| `undefined` | eligible — the ES6 default fires and silently reverts to the **Node clock**, the very bug this phase fixes |
| `null` | **not eligible** — `new Date(null)` is the Unix epoch, so `0 >= nextEligibleAt` is never true |
| `''` | **not eligible** — same |
| `0` | **not eligible** — same |

Once `now` comes from `row.dbNow`, a null column (driver quirk, hand-edited fixture, future query
variant) silently defers **every candidate row forever**, emitting `[RETRY-DEFER]` lines that look
normal. That is the same class of invisible stall this phase exists to eliminate, arriving from the
opposite direction. SPEC RETRY-S4 requires that "both values in the comparison originate from the same
clock"; a null or missing `dbNow` violates that, so the guard belongs here.

Output: a helper whose fail-open guarantee covers all three inputs, and a JSDoc that tells the truth
about the clock basis and about how operators must read `nextEligibleAt`.

Decisions implemented (CONTEXT traceability) — D-02: signature and return shape unchanged
(`{ lastErrorAt, intervalMinutes, now }` -> `{ eligible, nextEligibleAt }`) · D-04: the known
consequence — `nextEligibleAt.toISOString()` renders server-local wall clock with a `Z` suffix — is
documented in the code · D-12 #2: a helper test with an injected `now` using values a 360-minute skew
would wrongly rule eligible.
</objective>

<!-- Contract after this plan. Plans 20.2-03 / 20.2-04 consume it directly — do not re-explore. -->
computeRetryEligibility({ lastErrorAt, intervalMinutes, now }): { eligible: boolean, nextEligibleAt: Date|null }

  lastErrorAt falsy or unparseable      -> { eligible: true, nextEligibleAt: null }   (unchanged)
  intervalMinutes unusable              -> treated as 0, i.e. eligible now            (unchanged)
  now missing / null / '' / 0 / NaN     -> falls back to the process clock (fail OPEN) [NEW]
  otherwise                             -> eligible = now >= lastErrorAt + intervalMinutes  (>= inclusive)

Callers MUST pass a `now` that came from the SAME SELECT statement as `lastErrorAt`
(`GETDATE() AS dbNow`). The helper cannot detect a violation — the SQL-shape tests in plans
20.2-03 / 20.2-04 are the net for that half.
</interfaces>

| `config.retry.interval.{payment,po}` -> `Date` math | Boot-range-guarded integers; never interpolated into SQL. |

No endpoint, no auth surface, no operator input, no SQL emitted by this plan. `src/utils/RetryPolicy.js`
is a pure module.
