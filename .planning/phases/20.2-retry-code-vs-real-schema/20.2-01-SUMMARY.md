## The contract, as shipped

**Parameter name and shape** — added to the existing destructured object, not as a second positional argument:

```javascript
function buildErrorStatsApply({ fesaTable, joinColumn, joinKey, dbAlias, dbColumn, timestampColumn } = {}) {
    if (timestampColumn !== 'lastUpdate' && timestampColumn !== 'none') {
        throw new Error('buildErrorStatsApply: invalid timestampColumn ' + timestampColumn);
    }
```

**Exact throw message:** `buildErrorStatsApply: invalid timestampColumn <value>` — built with `+` concatenation (never a template literal), matching `getRetryIntervalMinutes` at `src/utils/RetryPolicy.js:38` and `buildScopeWhere` at `:126`.

**Closed value set:** exactly `'lastUpdate'` and `'none'`. Strict equality, so case variants are rejected. `undefined`, `null`, `''`, `'lastupdate'`, `'LastUpdate'`, `'None'` and `'createdAt'` all throw — each asserted in the suite.

**Emitted SELECT line, both branches:**

| `timestampColumn` | Target table | Emitted line 2 (4-space indent included) |
|---|---|---|
| `'lastUpdate'` | `fesa.dbo.fesaOCFocaltec` | `    SELECT COUNT(*) AS errorCount, MAX(lastUpdate) AS lastErrorAt` |
| `'none'` | `fesa.dbo.fesaPagosFocaltec` | `    SELECT COUNT(*) AS errorCount, CAST(NULL AS datetime) AS lastErrorAt` |

Full payments fragment as emitted today:

```sql
OUTER APPLY (
    SELECT COUNT(*) AS errorCount, CAST(NULL AS datetime) AS lastErrorAt
    FROM fesa.dbo.fesaPagosFocaltec
    WHERE NoPagoSage = P.DOCNBR
      AND idCia = 'COPDAT'
      AND status = 'ERROR'
) AS ef
```

**OC byte-identity — verified, not asserted by eye.** The `HEAD~1` copy of `RetryPolicy.js` was loaded alongside the new one and their outputs compared as whole strings:

## `lastErrorAt` is structurally always NULL for payments

`fesa.dbo.fesaPagosFocaltec` genuinely has no timestamp column (`idCia`, `NoPagoSage`, `status`, `idFocaltec` — 2026-07-27 production read of `fesa.INFORMATION_SCHEMA.COLUMNS`). The typed NULL is not a placeholder for data that exists elsewhere; **there is no payment error time to read**, and there is nothing writing `status='ERROR'` for payments in the first place (production distribution: `PAID 2678 / PARTIAL 27 / SYNCED 3 / REVERTED 2`, zero `ERROR`).

Consequence to carry forward: every payment row hands `computeRetryEligibility` a `null` `lastErrorAt`, which the helper treats as "never failed → eligible immediately" (RETRY-C4). **The 30-minute payment interval is therefore inert for payments until CR-03 (deferred) provides somewhere to record a failure and its time.** That is a faithful representation of the data that exists today, not a regression: it is exactly the behaviour of the pre-Phase-20 code. When CR-03 lands, this becomes a one-line swap of the `'none'` branch.
