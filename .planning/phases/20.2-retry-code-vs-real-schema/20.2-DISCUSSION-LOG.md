## Single-clock source

| Option | Description | Selected |
|--------|-------------|----------|
| `GETDATE() AS dbNow` column | Add the server clock as an extra column in the same SELECT and pass it as `now`. Both operands come from the same server, so any driver-level reinterpretation cancels out of the subtraction. Helper contract unchanged. | ✓ |
| `DATEDIFF` computed in SQL | Have SQL return elapsed minutes directly; the helper compares integers. Immune to DST and future driver changes, but `nextEligibleAt` must be reconstructed — either by interpolating the interval into the SQL string or recomputing in JS. | |
| Compensate with a measured offset in JS | Subtract a known offset in JavaScript. Rejected outright — fragile, and breaks at the DST transition in October. | |

**User's choice:** `GETDATE() AS dbNow` column
**Notes:** Chosen because it is the smallest change that provably fixes the defect while preserving Phase 20.1's D-01 (eligibility lives in exactly one place) and keeping `nextEligibleAt` derivable for the `[RETRY-DEFER]` operator log without new SQL interpolation. The `DATEDIFF` option is objectively more robust; it was rejected on the grounds that it adds surface area to a fix whose purpose is to reduce risk, and its extra robustness buys nothing observable while CR-04 remains unfixed. Flagged for revisit if the CR-04 `ALTER TABLE` ever lands. Accepted consequence recorded as D-04: the logged `nextEligibleAt` renders server-local time with a `Z` suffix and must be read as Mexico time.

## buildErrorStatsApply signature

| Option | Description | Selected |
|--------|-------------|----------|
| Optional parameter with a safe default | `timestampColumn = 'lastUpdate'` — no call site has to change except the payment ones. | |
| Required parameter that throws when absent | Every one of the 5 call sites must declare its table shape. A missing argument fails loudly instead of generating invalid SQL. | ✓ |
| Two separate exported functions | One builder per table shape. Explicit, but duplicates the fragment. | |

**User's choice:** Required parameter that throws when absent
**Notes:** Decided on the strength of the project's own history rather than general principle. `CLAUDE.md` §6 pitfall #2 records that PR #16 changed a shared util's implicit default and silently broke 7 callers, repaired only in PR #19. An optional default here would recreate that exact pattern — correct for OCs, silently invalid for payments. Throwing on a missing argument also matches the posture `getRetryIntervalMinutes` established in Phase 20.1. Discovery during this area: `background.js` does **not** use the helper — it hand-writes its own `OUTER APPLY` at L492-502 — so it is a sixth emission site that a caller-following planner would miss. Recorded as D-09.

## EOM payments table

| Option | Description | Selected |
|--------|-------------|----------|
| Drop the column for payments + footnote | Payments table has no error-description column; one footnote states that the detail is not recorded yet. Tables are deliberately asymmetric. | ✓ |
| Keep the column with a fixed placeholder | Show "no registrado" so both tables look identical. | |
| Remove payments from the EOM email entirely | Wait until real error data exists. | |

**User's choice:** Drop the column for payments + footnote
**Notes:** A column that always reads the same trains the operator to ignore it, and normalises the gap. A single honest footnote keeps visible pressure to resolve CR-03. The POs table is untouched — `responseAPI` genuinely exists on `fesaOCFocaltec` and carries real data.

## Skew-resistance test strategy

| Option | Description | Selected |
|--------|-------------|----------|
| Helper unit test with an injected `now` | Catches a revert to `new Date()`. | |
| SQL-shape test | Catches removal of `GETDATE() AS dbNow` from the SELECT. | |
| All three (helper + SQL-shape + repo-wide schema guard) | Each catches a regression the others cannot; the schema guard also covers files this phase never touches. | ✓ |

**User's choice:** All three
**Notes:** The user had offered to delegate this area entirely to Claude; the recommendation was written out anyway so the user knows what is being built. The decisive argument was that the first two tests are not redundant — one catches "the data stops being provided", the other catches "the data is provided but ignored" — and neither catches a future query written elsewhere against `fesaPagosFocaltec`, which is what the third covers.
