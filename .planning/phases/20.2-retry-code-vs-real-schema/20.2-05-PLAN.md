<objective>
Make the end-of-month payments report work. Its query selects `responseAPI` and orders by `lastUpdate`
on `fesa.dbo.fesaPagosFocaltec` — neither column exists — so the statement throws, the `try/catch` at
`src/background.js:398-402` logs a warn and continues with no rows, and the payments email has always
read "Sin pendientes". Drop the impossible column from both the query and the rendered table, and state
the gap once, honestly, in a footnote.

Purpose: the failure is invisible. The catch block's comment is "Continue to next tenant; partial data
better than no data" — for payments it is *always* no data, and the email that results looks like good
news. An operator reading "Sin pendientes" at month end concludes nothing failed.

Output: a schema-valid payments EOM query, a payments email table with five columns and a footnote, and
a POs path that is provably byte-identical.

Decisions implemented (CONTEXT traceability) — D-09: `background.js` hand-writes its own `OUTER APPLY`
and is a **sixth** emission site that `buildErrorStatsApply`'s call sites do not lead to · D-10: the
error-description column is **removed**, not filled with a placeholder — a column that always reads "no
registrado" trains the operator to ignore it and normalises the gap; one footnote tells the truth once
and keeps visible pressure to resolve CR-03 · D-11: the POs table is unchanged; `responseAPI` genuinely
exists on `fesaOCFocaltec` and carries real data, so the two tables are deliberately asymmetric.

**Two corrections to CONTEXT.md, confirmed against the source:** (1) `buildEomEmailHtml` lives in
`src/utils/EomNotification.js:103-156`, not in `background.js` — `background.js` only calls it at L406.
The *query* defect is in `background.js`; the *rendering* is in `EomNotification.js`, and both files are
in scope. (2) `isPos` at `EomNotification.js:105` currently drives only the intro sentence; the table
header (L131) and the row template (L140-147) are category-blind, so the header cell and the body cell
must branch **together** or the table renders six headers over five cells.
</objective>
