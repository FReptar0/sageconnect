**Notes:** Surfaced during the discussion and recorded in CONTEXT.md `<deferred>`: a Sage-cancelled PO loses its `POSTED` row (`PortalOC_Canceller.js:100` UPDATEs it to `CANCELLED`), so it reaches the cron with `errorCount = 0`, skips the probe, and absorbs one 409. ## Claude's Discretion

All four gray areas were delegated. Decisions taken (full rationale in `20.3-CONTEXT.md`):

| ID | Decision | Deciding criterion |
|---|---|---|
| D-01 | Probe runs first in the loop body, **before** Joi validation, as an early `continue` | Avoids a Joi `ERROR` row that would inflate `errorCount` for an already-resolved OC; also the smaller diff |
| D-02 | `errorCount` reaches the loop via a function-scoped `Map` built from `recordset` | Avoids modifying the shared `groupOrdersByNumber` / `parseExternPurchaseOrders` utils (CLAUDE.md §6 #2 blast radius) |
| D-03 | New `src/utils/GetPurchaseOrders.js`, mirroring `GetProviders.js` structurally | CLAUDE.md §7 routes shared helpers to `utils/`; a service layer for one consumer is unnecessary complexity |
| D-04 | Three-outcome discriminated object — **must not** copy `getProviderByExternalId`'s `null`-for-everything contract | That contract conflates "absent" with "unreachable", which RETRY-D2 forbids outright |
| D-05 | The `^[0-9a-fA-F]{24}$` guard lives in the helper, not the controller | Satisfies RETRY-D8 structurally — a malformed id never reaches the controller, so no path exists for it to reach SQL |
| D-06 | Two labels: `[PORTAL-CHECK]` per row with a `result=` field, `[PORTAL-CHECK-SUMMARY]` per tick | Mirrors the existing `[RETRY-DEFER]` / `[RETRY]` pair; the label set cannot grow as branches are added |
| D-07 | Two new suites; the `ef.errorCount` SQL-shape assertion extends `cron-where` | Behavioural tests must not be able to break SQL-shape anchors, and vice versa (same separation 20.2 used for `schema-guard.test.js`) |
| D-08 | Mirror `tests/utils/GetProviders.test.js`, **not** `tests/GetProviderByExternalId.test.js` | The latter is a live-portal CLI script despite its `.test.js` name — copying it would produce a manual script, not a unit test |
| D-09 | Mock `src/utils/PortalClient`, plus `src/config` (Pattern S-9) and `LogGenerator` | The established line in `tests/utils/GetProviders.test.js:34` |
| D-10 | `mockReset()` every shared mock in `beforeEach` | 20.1-02 proved `clearAllMocks()` does not drain queued `mockResolvedValueOnce`; the new suites queue per-case responses and are exposed to exactly that bug |

Remaining latitude left to the planner: JSDoc wording, parameter ordering, internal variable names, whether the behaviour table is a `switch` or a lookup, test case naming, and whether `[PORTAL-CHECK-SUMMARY]` is emitted when `probed=0`.
