**⚠️ The D3 assertion pair MUST be alias-prefixed on both halves.** `buildErrorStatsApply`
(`RetryPolicy.js:204-206`) emits into the OUTER APPLY subselect:

```javascript

        ? 'SELECT COUNT(*) AS errorCount, MAX(lastUpdate) AS lastErrorAt'
        : 'SELECT COUNT(*) AS errorCount, CAST(NULL AS datetime) AS lastErrorAt';
```

So the emitted SQL **already contains** the bare substrings `errorCount` and `lastErrorAt`, today,
before any change — and L107 above **asserts** that `MAX(lastUpdate) AS lastErrorAt` is present.
Therefore:

- ✅ `expect(sqlPassed).toMatch(/ef\.errorCount/)` — meaningful; only the new projection produces it.

### Q2 — Where is `errorCount` dropped, and where does the `Map` go?

**The drop is confirmed, and it happens in two stages.**

Stage 1 — `src/utils/OC_GroupOrdersByNumber.js:11-27` **keeps** the field but **lowercases the key** and trims strings:

```javascript

        // usar NUM (A.PONUMBER) como clave, limpiando espacios
        const key = (r.NUM ?? '').toString().trim();

        if (!ordersMap[key]) {

So `errorCount` → `order.errorcount`, `EXTERNAL_ID` → `order.external_id`, `dbNow` → `order.dbnow`.

whitelist object literal, and `errorcount` is not in it:

        requisition_number: po.requisition_number

```

**D-02 is therefore correct and mandatory** — `errorCount` cannot reach the loop without either a `Map`
or an edit to that whitelist (which is a shared util used elsewhere: the CLAUDE.md §6 #2 blast-radius trap).

**Exact build site: a new statement at L261, immediately before `const grouped = groupOrdersByNumber(recordset);` (L262).** Current context (`L261-267`):

```javascript

    const po = ordersToSend[i];
```

Build from the **post-filter** `recordset` — note `recordset` is reassigned at L234 by the retry filter,
so at L261 it is exactly the set that becomes `ordersToSend`. Keying:

- **Map key:** `String(row.EXTERNAL_ID || '').trim()` — `EXTERNAL_ID` is uppercase on `recordset` rows, produced by `RTRIM(A.PONUMBER) as [EXTERNAL_ID]` (`PortalOC_Creator.js:97`).
- **Loop lookup key:** `String(po.external_id || '').trim()` — the loop's available key, lowercase, per `parseExternPurchaseOrders.js:91`.
- One row per PO **line**, so many rows share one `EXTERNAL_ID`; `errorCount` is identical across them (`COUNT(*)` from the OUTER APPLY, correlated on `A.PONUMBER`). Last-write-wins is safe.
- Default on miss: `|| 0` → `errorCount = 0` → **no probe**. Correct fail-direction: an unmapped OC behaves exactly as it does today.

**Hazard — guard the `.trim()`.** `(po.external_id || '')` rather than `po.external_id.trim()`. A `null`/

the whole cron tick mid-batch (CLAUDE.md §3; `RetryPolicy.js` documents the same never-throw reasoning).
The `|| ''` idiom is already the codebase norm — `GetProviders.js:61`, `:80`, `:98`;
`OC_GroupOrdersByNumber.js:13` uses `(r.NUM ?? '')`.

**Always-on:** the `Map` is a `const` inside `createPurchaseOrders()`, unreachable once the function
returns. No module scope, no timer, no listener. Satisfies §3 with nothing to clean up.
