Create the OperationManager concurrency service and extend config.js with schedule settings.

Purpose: OperationManager is the foundation for all Phase 8 work -- it provides per-operation-type locks (preventing concurrent execution of the same operation), a global `background-cycle` lock (blocking ALL manual triggers while cron runs), EventEmitter-based progress events (for SSE streaming), and bounded execution history (for /schedule/history endpoint). Config.js gets the schedule section needed by CronScheduler and background.js.

    - acquireLock('payment-reconciliation', 'op-2') returns false when 'payment-reconciliation' lock already held

    - acquireLock('po-upload', 'op-4') returns false when 'background-cycle' lock is held (global lock blocks all)
    - releaseLock('payment-reconciliation') frees the lock, subsequent acquireLock returns true
    - getRunningOperations() returns object with currently locked operation types and their metadata
    - emitProgress('op-1', { type: 'progress', operation: 'bg', tenant: 'T1', step: 'buildProviders', message: 'test', timestamp: '...' }) emits event on `progress:op-1`
    - Subscriber receives emitted progress event with correct shape
    - addHistory({ taskId, operationId, startedAt, finishedAt, success, errors, summary }) pushes to ring buffer
    - getHistory() returns all entries; after 101 pushes, oldest entry is evicted (max 100)
    - getHistory(1) returns only entries from last 1 hour
    - config.schedule.cronExpression defaults to '*/15 * * * *' when CRON_SCHEDULE not set
    - config.schedule.operationDelayMs defaults to 5000 when OPERATION_DELAY_MS not set
    - config.schedule.operationDelayMs parses string env var to integer

  <action>
    1. Run `npm install node-cron@4` to add the scheduler dependency (needed by Plan 02 but installed here to keep Wave 1 self-contained).

    2. Create `src/services/OperationManager.js` as a singleton class extending EventEmitter:
       - `constructor()`: Initialize `this.locks = new Map()` for operation-type locks, `this.history = []` as ring buffer (max 100), set `this.setMaxListeners(20)`.
       - `acquireLock(operationType, operationId)`: If `this.locks.has('background-cycle')` AND operationType !== 'background-cycle', return false. If `this.locks.has(operationType)`, return false. Otherwise set `this.locks.set(operationType, { operationId, startedAt: new Date().toISOString() })` and return true.
       - `releaseLock(operationType)`: Delete from locks Map.
       - `isLocked(operationType)`: Returns true if operationType is locked OR background-cycle is locked.
       - `emitProgress(operationId, event)`: Call `this.emit('progress:' + operationId, event)`.
       - `getRunningOperations()`: Return `Object.fromEntries(this.locks)`.
       - `addHistory(record)`: Push record to `this.history`, shift if `this.history.length > 100`.
       - `getHistory(hours)`: If hours provided, filter entries where startedAt is within the last N hours. Otherwise return all.
       - Export as singleton: `module.exports = new OperationManager()`.

    3. Update `src/config.js`: Add a `schedule` section to the config object AFTER the `security` section:

       ```javascript
       schedule: {

       },
       ```
       Do NOT add CRON_SCHEDULE or OPERATION_DELAY_MS to the REQUIRED validation -- they have defaults and are optional.
