<objective>
Migrate both cron controllers' JS retry post-filter from the removed geometric backoff to the shared
fixed-interval eligibility helper — POs use `config.retry.interval.po` (240 min), payments use
`config.retry.interval.payment` (30 min) — and rename the `[BACKOFF*]` operator log labels to
`[RETRY*]`, preserving the exact field shape. Rewrite both `*.cron-where.test.js` suites to prove the
four eligibility outcomes with zero geometric-curve assertions.

Purpose: This is the highest-blast-radius change in the phase (RETRY-C4). Routing every row through
`computeRetryEligibility` means the "first upload is not a retry" rule lives in exactly one place, so a
never-failed PO/payment can never be wrongly deferred and stall the cron.

Output: Two controllers whose eligibility math is document-type-differentiated and centralized; two
green four-case integration suites; a clean full-suite baseline.

Decisions implemented (CONTEXT traceability) — D-01: single shared eligibility helper (adopted in both controllers; first-attempt rule lives in one place) · D-04: errorCount is log-only (attempts=), never timing math · D-05: [BACKOFF*]→[RETRY*] label rename keeping the exact field shape · D-08: two-layer test shape (integration half — both cron-where suites).
</objective>

getRetryIntervalMinutes(intervalConfig, docType): number
  - intervalConfig === config.retry.interval === { payment: number, po: number }
  - docType 'payment' -> intervalConfig.payment (30 default); 'po' -> intervalConfig.po (240 default)
  - throws on unknown docType

computeRetryEligibility({ lastErrorAt, intervalMinutes, now }): { eligible: boolean, nextEligibleAt: Date|null }
  - lastErrorAt falsy (first attempt) -> { eligible: true, nextEligibleAt: null }
  - else nextEligibleAt = lastErrorAt + intervalMinutes; eligible = now >= nextEligibleAt (>= inclusive)
