## Contract for wave 2 (plans 20.1-02 / 20.1-03 — read this section first)

### Final exports of `src/utils/RetryPolicy.js`

```js
module.exports = { getRetryIntervalMinutes, computeRetryEligibility, buildScopeWhere, buildErrorStatsApply };
```

### `getRetryIntervalMinutes(intervalConfig, docType) -> number`

- `intervalConfig` is `config.retry.interval`; `docType` is the string `'payment'` or `'po'`.
- Returns `intervalConfig.payment` (30 by default) or `intervalConfig.po` (240 by default).
- **There is no error-count parameter.** Any extra argument is ignored — a caller cannot reintroduce attempt-based growth.
- Unknown `docType` throws `Error('getRetryIntervalMinutes: invalid docType ' + docType)`. Matching is exact and case-sensitive (`'PO'` throws).

### `computeRetryEligibility({ lastErrorAt, intervalMinutes, now }) -> { eligible, nextEligibleAt }`

- `lastErrorAt` falsy (no prior ERROR row) → `{ eligible: true, nextEligibleAt: null }`. **This is the first-attempt rule — do not re-implement it at the call site.**
- Otherwise `nextEligibleAt = new Date(lastErrorAt) + intervalMinutes` minutes, and `eligible = now >= nextEligibleAt` (**`>=` inclusive**).
- `lastErrorAt` may be a `Date` or a string (mssql may hand back either).
- `now` defaults to `new Date()`; pass it explicitly in tests to pin the boundary.
- Fails open: unusable `intervalMinutes` (missing/NaN/Infinity/negative/string) is treated as 0 → eligible now; unparseable `lastErrorAt` → `{ eligible: true, nextEligibleAt: null }`.
- `nextEligibleAt` is a `Date` in every non-first-attempt case — it is what the `[RETRY-DEFER]` log line and the diagnostic's section 6 should print.

Typical wave-2 call shape:

```js
const intervalMinutes = getRetryIntervalMinutes(config.retry.interval, 'po'); // or 'payment'
const { eligible, nextEligibleAt } = computeRetryEligibility({ lastErrorAt: row.lastErrorAt, intervalMinutes });
```

`ef.errorCount` from `buildErrorStatsApply` is still available but no longer feeds any timing math (D-04) — keep it only as `attempts=` operator log context.

- **Nested `config.retry.interval` over a flat `intervalPaymentMin`** — CONTEXT D-02 (locked) supersedes the SPEC's illustrative flat form; it mirrors the `config.retry.backoff` namespace it replaces and keeps `config.retry.*` symmetric.

- **Obsolete-var WARN placed immediately after the interval guards**, not with the API-key warning at the end, so RETRY-C3's three pieces (env read, guards, obsolete warning) stay contiguous for a maintainer.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] Fail-open guards in `computeRetryEligibility`**
- **Found during:** Task 1 (GREEN implementation)
- **Issue:** The plan's literal formula (`nextEligibleAt = new Date(new Date(lastErrorAt).getTime() + intervalMinutes * 60000)`, `eligible = now >= nextEligibleAt`) yields `Invalid Date` when `intervalMinutes` is `undefined`/`NaN` or `lastErrorAt` is unparseable. Every comparison against `NaN` is `false`, so the affected row would be deferred **forever** and silently — invisible to the operator and unbounded. `getRetryIntervalMinutes` can legitimately return `undefined` if a caller passes the wrong config object, which makes this reachable rather than theoretical.
- **Fix:** Non-finite/non-positive `intervalMinutes` is treated as 0 (eligible now); unparseable `lastErrorAt` returns `{ eligible: true, nextEligibleAt: null }`. This preserves the SPEC's stated highest-blast-radius invariant (a document must never be wrongly deferred) and matches the fail-open posture of the removed `computeBackoffWaitMinutes`, which also returned 0 for invalid input.
- **Files modified:** `src/utils/RetryPolicy.js` (+ one covering test in `tests/utils/RetryPolicy.test.js`)
- **Verification:** dedicated test — all of `undefined, null, NaN, Infinity, -10, 'abc'` as `intervalMinutes`, plus `lastErrorAt: 'not-a-date'`, yield `eligible: true`.
- **Committed in:** `1b4f269` (Task 1 GREEN commit)

**2. [Rule 3 - Blocking] `buildErrorStatsApply` JSDoc rewritten despite the "byte-for-byte" instruction**
