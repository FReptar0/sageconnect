## Retry eligibility (helper shape)

| Option | Description | Selected |
|--------|-------------|----------|
| Shared eligibility helper | One helper in `RetryPolicy.js` encapsulates the whole rule (first-attempt eligible + `now−lastErrorAt ≥ interval`), called by both controllers + the diagnostic; first-attempt rule (RETRY-C4) cannot diverge between call sites. Follows Phase 20 D-01/D-05. | ✓ |
| Getter delgado + check inline | Helper returns only the interval number per type; each controller re-checks `now−lastErrorAt` itself. Smaller change but duplicates the first-attempt logic in two places. | |

**User's choice:** Delegated to Claude — *"revísalo, no tengo conocimiento, me dieron solo el proyecto, el sr se fue."*
**Notes:** Claude selected the shared eligibility helper because RETRY-C4 (first-attempt document must stay immediately eligible) is the highest-blast-radius regression — centralizing the rule in one helper makes it impossible to get right in one controller and wrong in the other.

## Obsolete env var WARN

| Option | Description | Selected |
|--------|-------------|----------|
| `console.warn` at config load, list-driven | Iterate the removed `RETRY_BACKOFF_*` names present in `process.env`; one `[CONFIG WARN]` per var, pointing to `RETRY_INTERVAL_*`. Matches `[CONFIG ERROR]`'s `console.error` (winston unavailable at load). Non-fatal. | ✓ |
| No WARN, only `.env.example` | Document the change in `.env.example`; emit nothing at runtime. Less noise, but the operator isn't told their `.env` has dead lines. | |

**User's choice:** `console.warn` at config load, list-driven (recommended).
**Notes:** Implements the uptime-preserving obsolete-var handling locked in SPEC RETRY-C3 (inert + warn, never fail-fast).
